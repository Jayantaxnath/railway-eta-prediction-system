Use these payloads in **`/docs` → prediction endpoint → Try it out → Execute**. These cover normal, boundary, optional-null, and invalid-input cases.

## 1. Normal running train

```json
{
  "train_id": "12345",
  "target_station_id": "GHY",
  "observed_at": "2026-09-04T19:30:00+05:30",
  "current_speed_kmph": 65.0,
  "average_speed_last_5_minutes": 60.0,
  "current_delay_minutes": 15.0,
  "distance_to_target_km": 120.0,
  "scheduled_time_to_target_minutes": 110.0,
  "rainfall_mm": 0.0,
  "congestion_score": 0.3,
  "historical_section_average_minutes": 125.0
}
```

## 7. Invalid: negative speed

This **should fail validation** with a `422 Unprocessable Entity`.

```json
{
  "train_id": "12345",
  "target_station_id": "GHY",
  "observed_at": "2026-09-04T20:15:00+05:30",
  "current_speed_kmph": -20.0,
  "average_speed_last_5_minutes": 40.0,
  "current_delay_minutes": 10.0,
  "distance_to_target_km": 50.0,
  "scheduled_time_to_target_minutes": 60.0
}
```

### Minimum test checklist

Test **#1, #2, #3, #4, #6, #7, and #8**. Record:

* HTTP status code
* ETA prediction
* delay/risk output
* model version
* whether invalid inputs correctly return `422`

One important edge case: **`distance_to_target_km = 0`** should be tested separately. If your model predicts something other than approximately `0` remaining minutes, you may want to add a backend rule that immediately returns arrival/0 ETA when the train is confirmed at the target station.
